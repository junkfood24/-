## 关键结果

| 负载 | 策略 | 窗口完成率（Mtask/s） | P99（µs） |
| --- | --- | --- | --- |
| 均匀 | FIFO / 本地 / 窃取 | 0.696 / 0.696 / 0.696 | 154.7 / 880.0 / 229.1 |
| 偏斜 | FIFO / 本地 / 窃取 | 0.696 / 0.497 / 0.696 | 172.1 / 759390 / 251.7 |
| 动态热点 | FIFO / 本地 / 窃取 | 0.697 / 0.483 / 0.697 | 186.4 / 764708 / 252.3 |

- 本地队列在偏斜/动态热点下分别丢弃 10.0%/12.8% 的请求，到 0.5 s 时仍积压 64 489/62 777 个任务；
  “完成数 / makespan”会得到 0.250/0.241，和丢弃率对不上，因此主表用固定窗口完成率。
- 阈值 k 从 1 增到 64：P99 从 222 µs 升到 4368 µs，窃取率从 0.45 降到 0.29 次/任务。
- 亲和感知窃取（仅派发端）：偏斜负载远程执行 23.3% → 19.7%，P99 284.2 → 276.1 µs（−2.8%）；
  均匀 10.5% → 4.2%，P99 −6.2%。不能宣称“远程降到零”。
- C++ 微基准（200 万任务，20 线程，3 轮中位数）：均匀 FIFO/本地/窃取 772.0/495.0/516.5 ms，
  偏斜 571.7/1326.2/511.4 ms。原始日志见 `results/bench_rounds.log`。

## 复现

## 数据集外部验证

`dataset_test/` 用课程组提供的 `KV_Scheduling_Benchmark_Student_20261104` 做了独立测试：

- 四种官方算法的 P99 排名为 **FIFO ≈ Priority > Steal ≫ Local**：FIFO/Priority 在 13/18 个主场景并列最低，Priority 在 4 个 T5 场景略优，Steal 只在 T4_K100 胜出，Local 从未胜出。这是“全局队列零锁/零竞争成本”的模型结论；A5 用 8%—10% 的 T1—T3 P99 代价换可扩展性，不是零成本下的绝对赢家。
- 官方 A5（最长队列受害者）相对 A4 本地队列，T1—T5 的 P99 组均值为 A4 的 5.7%—24.8%；D1 同键热点四种算法都被约 11 201 的键等待支配。
- 把 Chase-Lev 语义接入同一引擎后，k=0、零探测成本时与 A5 基本持平（12/18 场景不劣，平均比 0.983）；探测成本 0.05、且失败探测也计费时，只有 3/18 场景优于 A5（平均 1.84），空扫会把早停的收益吃回去。
- 关键修正：k=2 在 8 worker/70% 负载下会使 P99 退化为 A5 的 2.53—3.23 倍；阈值必须随队列深度缩放。主报告中的 k=2 只适用于其 20 线程、队列更深的场景。
- 该数据集不建模缓存/NUMA/锁竞争，因此不能验证 owner LIFO 的局部性收益；owner LIFO 与 FIFO 在测试中差异为 −6.8%…+1.0%，没有稳定优势。

详见 `dataset_test/KV数据集_任务窃取测试报告.pdf` 与 `dataset_test/README.md`。
